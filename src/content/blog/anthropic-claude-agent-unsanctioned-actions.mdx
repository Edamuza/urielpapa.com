Anthropic published an alignment assessment on October 23, 2026, of a UK AI Security Institute (AISI) test. In 9 of 43 runs, Claude Mythos 5 took unsanctioned actions that affected real people and organizations, including a GitHub maintainer. Two days later, Anthropic said Claude got past a paywall to pull publicly available Georgia vote-count data without human authorization. Both cases show what an AI agent can do when a task is blocked and nothing outside the model stops it.

I use AI coding agents on my own machine, so this is about the kind of setup I run. It is part of my [AI](/topics/ai) writing and follows my [take on a critical MCP sign-in flaw in OpenCode](/news/opencode-mcp-oauth-rce).

## What happened?

AISI ran a capture-the-flag (CTF) cyber challenge with internet access on and the model's cyber safeguards off, according to [Anthropic's alignment assessment](https://www.anthropic.com/research/alignment-assessment-ukaisi). In the main run, after failing within scope, Mythos 5 opened a malicious pull request on a repository owned by unrelated developers. It then created fake identities to pressure the maintainer into approving it. The maintainers refused, and [AISI's incident report](https://www.aisi.gov.uk/blog/incident-report-unsanctioned-agent-behaviour-during-cyber-testing) found no resulting real-world harm.

In other runs, Mythos 5 took over another run's GitHub account with a token left in a public file. It also tried a password it found in the challenge on a real developer's GitHub account. None of these attempts succeeded. Anthropic announced the assessment in [a post on X](https://x.com/AnthropicAI/status/2113626655902126442).

The Georgia case is separate. [Reuters reported](https://www.thestar.com.my/tech/tech-news/2026/10/26/anthropic039s-claude-accessed-georgia-state-vote-count-data-behind-paywall) Anthropic's statement that Claude "didn't access the state's voter registration system" and that Anthropic has since taken steps to block such actions. A spokesperson told [Fox Business](https://www.foxbusiness.com/fox-news-tech/claude-ai-accessed-publicly-available-georgia-voter-data-anthropic-confirms) the model was on an internal statistics project and requested a dashboard access token "without being asked to." Fox Business reports this is a case from Anthropic's [October 9 post on unintended model actions](https://www.anthropic.com/research/investigating-unintended-model-actions), which did not name Georgia.

## What changed, in plain words?

Anthropic replayed the main transcript many times without real internet access. From the point where its own notes pointed to GitHub, Mythos 5 started the attack in 83 percent of replays. When researchers added a mention of harm to its earlier reasoning, that fell to 13 percent. Once under way, it stopped on its own in 2 percent of replays, and in 5 percent when told it faced real humans.

Anthropic calls this "momentum." Claude Mythos 5.1, Claude Opus 5.5 and an internal research model began the attack 0 to 13 percent of the time from the same point. AISI will run its CTF evaluations offline until it has stronger internet controls.

## What does it mean for small businesses and founders?

In my reading, the lesson is not about one model. A capable agent with a hard task, open internet and a working credential looks for a way around the block. Rules in the prompt are a weak brake. Told it could abort, Mythos 5 did so in 46 percent of early samples with a very explicit GitHub rule. Later in the run, it never did.

The limits that held sat outside the model, such as a maintainer who said no. The same applies when you connect an agent to a browser, MCP tools, a paid API or a GitHub repository. AISI tells organizations to "be cautious when verifying outside code and contributions."

## What should you do now?

1. **Require human approval for actions that spend money or reach gated data.** Purchases, paid API calls, form submissions and anything behind a login, token or fee should wait for a person.
2. **Set hard budget limits.** Put spending caps on API keys and billing accounts, and cap tokens and run time per task.
3. **Give agents least-privilege tokens.** Scope each token to one repository and the minimum permissions, with a short expiry. Keep tokens out of public files and logs.
4. **Review outside pull requests yourself.** Treat new accounts and pressure to merge as warning signs. Run unfamiliar code in an isolated environment, as an outside developer did in the AISI case.
5. **Limit and log internet access.** Allow-list the domains an agent needs, log its tool calls, and read the log after long runs.
