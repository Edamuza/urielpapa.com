## The problem

SEO work on WordPress repeats the same checks and the same publishing steps on every site: headings, indexability, images, broken links, internal links, titles, descriptions and schema. Doing it by hand takes time, and a missed step goes live.

It became clear when we were publishing across several client sites at once and the same mistakes kept coming back: a missing meta description on one site, a page left on noindex on another. Checklists didn't stop it, so we built the checks into WordPress itself.

## What we built

Five plugins, about 11,700 lines of code in total:

- **An SEO diagnostic scanner** with content, heading, indexability, image and broken-link checks, plus spreadsheet exports.
- **An internal-link content graph** that shows how pages link to each other.
- **A publish guard** that requires an SEO title, a meta description and schema before a post can go out.
- **Bulk importers** for DOCX drafts and for schema CSV files.

## Stack and why

- **Platform:** WordPress.
- **Language:** PHP.

Our client sites ran on WordPress, so the tools had to live where the team already worked. Plain PHP plugins meant no extra service to host, and they worked alongside Yoast SEO and Rank Math instead of replacing them.

## Results

- 5 plugins and about 11,700 lines of code.
- Audits, internal linking, publishing rules and imports handled inside WordPress.

Writers dropped DOCX drafts into the importer, the scanner ran before each client report, and the publish guard stopped posts that were missing an SEO title or schema. The content graph helped us find pages with no internal links pointing to them.
